# 异环（NTE）店长特供 · 自动刷关

基于**屏幕图像识别 + 模拟鼠标键盘**的刷关脚本，附带图形控制面板。

针对《异环》「店长特供」里的 **1-1 新品练习**：自动开局 → 识别客人的番茄汁需求 → 交付 → 结算领取 → 回到准备页再来一轮。

> ⚠️ **免责声明**
> 本项目仅用于个人学习 Windows 自动化与计算机视觉技术。
> 游戏厂商通常禁止在联机游戏中使用第三方自动化工具，使用本脚本可能违反用户协议并导致账号风险，请自行评估后再决定是否使用。
> 本项目不含任何内存读写、注入、修改账号数据的代码，全部交互都通过操作系统公开 API（抓屏 + 模拟输入）完成。

## 这个版本能做什么

| 能力 | 说明 |
|---|---|
| 自动刷关 | 完整跑「开局 → 服务 2 位客人 → 结算领取 → 回到准备页」 |
| 指定轮数 / 刷空 | 跑固定轮数，或一直刷到都市活力为 0 |
| 自动选关 | 关卡没选对会自动点回 1-1；列表被滚动、章节被收起也能自己恢复 |
| 前置校验 | 每轮开始前校验「1-1 / 安魂曲+达芙蒂尔」；活力按模式区分（指定轮数不校验，刷空到 0 停） |
| 分辨率自适应 | 任意 16:9 分辨率（已实测 3840×2160 / 2560×1440 / 1920×1080 / 1600×900） |
| 图形面板 | 开始/停止、运行方式选择、实时日志、刷关要求说明 |
| 全局热键 | `F9` 优雅停止（跑完本轮）、`F7` 立即中断 |

- **Windows 10 / 11**（开发与验证环境：Windows 11 26200、4K 150% 缩放、双屏）
- **Python 3.10+**，需要自带 `tkinter`
- 依赖：

```bash
pip install opencv-python numpy
```

## 快速开始

### 1. 首次配置：生成识别模板

脚本靠模板比对识别界面，模板必须从**你自己的游戏画面**上截取一次。

1. 进入游戏，打开「店长特供」，停在关卡选择页
2. 选中 **1-1 新品练习**，并确保辅助雇员是 **安魂曲 + 达芙蒂尔**
3. 运行：

```bash
python build_templates.py
python build_shop_templates.py
```

会在 `assets/` 下生成全套模板。仓库里已带一份（来自 3840×2160），**同分辨率下可以直接用**；换了分辨率或改了 UI 才需要重建。

### 2. 启动面板

双击 **`启动刷关.vbs`**（无窗口闪动）或 `启动刷关.bat`，会提示 UAC，点「是」。

面板上：

1. 选「跑指定轮数」或「一直刷到活力用完」
2. 点 **开始刷关**
3. 面板自动隐藏，跑完自动弹回并显示结果

也可以直接用命令行（同样需要管理员）：

```bash
python nte_farm.py --serve 2 --rounds 5      # 刷 5 轮
python nte_farm.py --serve 2 --until-empty   # 刷到活力为 0
python nte_farm.py --dry-run                 # 只校验不点击
```

## 刷关要求（三条，缺一不可）

1. **关卡必须是「1-1 新品练习」**
   脚本会自动点选。列表被滚动过、章节被收起过，它会自己滚回顶部 / 展开章节，再按 1-1 那一行的**实际位置**点它。

2. **辅助雇员必须同时包含「安魂曲」和「达芙蒂尔」**
   少一个就停下并提示，不会硬刷。改法：准备页底部「替换雇员」。

3. **都市活力**（右上角 `X/700`）—— 按模式区分：

   | 模式 | 活力要求 |
   |---|---|
   | 跑指定轮数 | **不校验**，活力 0 也照跑 |
   | 一直刷到活力用完 | 活力为 0 时停下 |

   活力只影响结算奖励多少，**不影响能否开局**（实测 0 活力也能正常开局、服务、领取）。

## 每轮流程

```
准备页
  ├─ 校验 1-1 / 雇员 / 活力（不满足就自动纠正或停止）
  ├─ 点「开始营业」
  ↓
小游戏（约 2 分钟）
  ├─ 等客人需求气泡出现（番茄汁）
  ├─ 点右下角「玻璃杯」
  ├─ 点台面上的「番茄汁利乐包」
  ├─ 游戏自动交付（营业额 +25）
  └─ 重复 2 位客人
  ↓
ESC → 结算页「挑战成功」
  ├─ 点「领取」
  ↓
回到准备页 → 重新选中 1-1 → 下一轮
```

单轮实测约 **22～25 秒**（不含 2 分钟的关卡计时，因为服务完 2 位就 ESC 提前结束）。

## 热键

| 按键 | 行为 |
|---|---|
| `F9` | 优雅停止：跑完当前这一轮（含领取、回到 1-1）再退出 |
| `F7` | 立即中断：杀掉所有正在跑的刷关进程，游戏可能停在关卡中间 |

两个都是**系统级热键**，面板隐藏时、焦点在游戏里时都有效。

> `F7` 会按命令行匹配清理所有含 `nte_farm.py` 的进程，所以**即使任务不是从面板启动的也能停掉**。

## 工作原理

```
抓屏 (GDI BitBlt) → 缩放到规范 3840×2160 → 模板匹配 / 文字掩码 → 决策
                                                        ↓
                                              模拟输入 (SendInput)
```

几个关键设计：

**1. 规范坐标空间**
所有坐标常量都以 `3840×2160` 为基准，运行时按 `kx = 客户区宽/3840` 映射到真实窗口。点击坐标走 `ClientToScreen`，所以窗口化、换显示器都能用。

**2. 抓屏必须先声明 DPI 感知**
否则在 4K + 150% 缩放的机器上，`GetClientRect` 返回的是**逻辑像素**（2560×1440），抓出来的图只有左上角一块，右上角的活力值直接丢失。

**3. DirectX 游戏只能用屏幕抓取**
`PrintWindow` 抓出来是全黑的（D3D 不经过 GDI 绘制），所以只能从屏幕表面 BitBlt。代价是**游戏必须在前台且不被遮挡**。

**4. 需求气泡是多尺度匹配的**
气泡大小会随客人位置浮动（实测同一关内幅度约 15%），单尺度模板在气泡偏大时只有 0.46 分，会漏检。现在按 `(1.0, 1.08, 1.15)` 三档匹配取最高分：

| 样本 | 单尺度 | 多尺度 |
|---|---|---|
| 气泡偏大（1.15×） | 0.457 ✗ | **0.873** ✓ |
| 气泡标准大小 | 1.000 ✓ | **1.000** ✓ |
| 无客人 | 0.387（正确排除） | **0.396** ✓ |

**5. 判断「选中的是不是 1-1」看右侧大标题**
左侧列表的粉色描边有歧义——选中的行是「紫底 + 洋红描边」，而鼠标悬停的行**只有洋红描边**。只看描边会把悬停行当成选中行。现在以右侧标题模板为准（1-1 得 0.97~1.00，1-3 得 0.50），跟列表滚动完全无关。

**6. 为什么必须管理员权限**
游戏进程以「高完整性级别（High）」运行。普通权限脚本发出的 `SendInput` 事件能进入系统输入流（`GetAsyncKeyState` 能读到），但**送不到游戏窗口**——Windows 的 UIPI 会在投递阶段静默丢弃，表现为「点了完全没反应」，而且窗口不会被激活。所以面板启动时会自己请求提权。

## 常见问题

**Q：点「开始」后面板消失了？**
正常。跑完会自动弹回。期间按 `F7`/`F9` 也能让它提前回来。

**Q：运行期间能切窗口 / 最小化吗？**
不能。DirectX 画面只能从屏幕表面抓，被别的窗口盖住就识别不到。脚本有超时保护不会乱点，但这一轮会白跑。

**Q：提示「条件不满足: 辅助雇员缺少 XXX」？**
准备页底部「替换雇员」，把安魂曲和达芙蒂尔都选上。

**Q：提示「选中的不是 1-1」并停下了？**
现在会自己点回 1-1（最多 6 次，含滚动和展开章节）。如果还是失败，把 `farm_log.txt` 发出来看现场。

**Q：换了显示器 / 分辨率还能用吗？**
16:9 的任意分辨率都自适应。**非 16:9（如 21:9 超宽屏）需要在该分辨率下重建模板**，面板会给出 `⚠ 非 16:9` 提示。

**Q：`F7` 按了没反应？**
先看 `hotkey_log.txt` 里有没有「注册热键: F9=True F7=True」和「收到热键 id=2」。如果注册是 False，说明 F7 被别的软件占用了，改 `nte_gui.py` 里的 `VK_F7` 换一个键。

**Q：日志在哪？**
`farm_log.txt`（刷关流程）、`hotkey_log.txt`（热键注册与触发）。

## 已知限制

- **必须前台运行**，不能后台/最小化跑（DirectX + GDI 抓屏的固有限制）
- **只支持 16:9**；非 16:9 需要重建模板
- **只针对 1-1 关卡**；其它关卡的商品/目标不同，需要重新标定
- **依赖固定的 UI 布局**：游戏大版本更新导致界面改版时，需要重跑 `build_templates.py` 和 `build_shop_templates.py`
- 识别是纯图像比对，**没有读取游戏内存**，所以对动画、遮挡、特效比较敏感

## 开发说明

`validate.py` 用来验证识别能力，重点是**做正负样本交叉对照**，而不是拿同一张图自比自（那样分数必然是 1.000，等于没验证）：

```bash
python validate.py              # 直接抓当前游戏画面（需停在准备页、窗口在前台）
python validate.py shot.png     # 或指定一张截图
```

输出示例（实时抓屏）：

```
A. 1-1 文字模板 vs 各关卡行
   y= 468  corr=+0.033      ← 1-0
   y= 702  corr=+1.000      ← 当前选中(1-1)
   y= 936  corr=+0.150      ← 1-2

B. 头像交叉匹配
   模板/槽位        槽位1     槽位2
   安魂曲          1.000    0.215
   达芙蒂尔         0.271    1.000
```
